## Minimal Stage 1 architecture (PROPOSED)
Use a single-process Python service/library with SQLite persistent storage, WAL mode, foreign keys, explicit write transactions and one database-owned monotonically increasing message sequence. Keep HTTP/connector transport as a thin later adapter; implement and test the engine locally first. This is a proposal, not an adopted technology decision.

Identifiers: opaque UUID room_id and message_id; immutable room_id and message_id; global integer event_seq allocated by SQLite to establish a stable ordering and cursor position. Room names are editable display labels, never keys. Each message has room_id, message_id, event_seq, principal_id, UTC created_at, text, and optional client_request_id (unique per principal for retry idempotency). Use UTC ISO-8601 with explicit timezone. No message edit/delete in Stage 1.

Tables: rooms(room_id PK, name, created_at, created_by); messages(event_seq INTEGER PRIMARY KEY, message_id UNIQUE, room_id FK, author_principal, created_at, text, client_request_id, UNIQUE(author_principal,client_request_id)); cursors(room_id, reader_principal, through_seq, updated_at, PK(room_id,reader_principal)). Index messages(room_id,event_seq). SQLite data file must live outside public GitHub; schema/migrations are versioned in component only.

Cursor rules: `read(room, after_seq, limit)` is side-effect free; `ack(room, through_seq)` is a separate explicit monotonic operation, bounded to an existing message in that room; never auto-ack on fetch. Own messages are not classified unread for the same principal. Context/history and unread classification are distinct views. Do not advance past unconsumed unseen messages by accident; acknowledge only an explicitly displayed/processed through-position. Cross-room cursors never mix.

## Minimal interfaces (PROPOSED)
- `create_room(name, actor_context) -> Room`; `list_rooms(actor_context) -> [Room]`.
- `post_message(room_id, text, actor_context, client_request_id) -> MessageReceipt`; returns committed message_id and event_seq; no success receipt before commit.
- `read_messages(room_id, after_seq, limit, actor_context) -> [Message]`; `get_cursor(room_id, actor_context) -> Cursor`; `ack_cursor(room_id, through_seq, actor_context) -> Cursor`.
- Later text-only adapter: `POST /rooms`, `GET /rooms`, `GET /rooms/{id}/messages?after=&limit=`, `POST /rooms/{id}/messages`, `GET/PUT /rooms/{id}/cursor`. No network listener in Stage 1.
- Identity seam: `ActorContext(principal_id, role, verified_by)` supplied by trusted adapter, never parsed from message body, request-supplied author, room label or sign-off. Until Stage 2 authentication exists, local testing uses explicit injected test principals and denies remote exposure. No deletion/clear endpoints.
