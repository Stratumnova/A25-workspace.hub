# Build Requests — A25 Systems Hub

Owner: Zed
Status: Proposal intake and review, not build authorization

Place proposed plans for new Systems Hub components here **before** they become approved project build instructions. The original proposal stays identifiable with its author, status and source. Workshop and other authorized teams may submit for review; no proposal authorizes implementation merely because it is filed here.

## Approval path

1. A team submits a component proposal here, with its scope, dependencies, risks, tests and requested decisions.
2. Zed reviews and explicitly approves, rejects or requests revisions. Record the decision and exact approved scope separately.
3. Only after approval, place a clearly identified approved version in the corresponding permanent component folder (for example [A25chatroom](../A25chatroom/README.md)). Preserve the proposal and its history here; do not silently overwrite it.
4. Formal Office work orders and separate implementation permissions are still required. An approved plan is not proof of built or tested code.
