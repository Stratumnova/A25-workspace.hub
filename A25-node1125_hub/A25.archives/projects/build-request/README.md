# Build Requests — Project Workspace Approval Staging

Owner: Zed
Status: Request and draft area; not an approved component workspace
Scope: Proposed project/component folder layouts, onboarding, team exchange lanes and setup plans

## Approval workflow

1. Prepare a proposed component workspace under this build-request area before placing approved setup documents in its permanent project folder.
2. Include a draft README/onboarding plan, intended location, team inbox/outbox layout, role boundaries, unresolved questions and source links.
3. Request Zed's explicit approval. Do not interpret draft publication, team review, GitHub commits or project-folder existence as owner approval.
4. After approval, publish the **approved version** to its permanent component location, preserving a link to the request, the owner decision and any changes.
5. From then on, keep the component at that same permanent location for building, testing, fixes, recovery and ZIP packaging. Main build integrates verified components; it does not move their development homes.

Formal Office work requests, orders and response reports remain in Office; this folder stages proposed workspace structures and documents for owner review. The existing A25 Chatroom setup was written before this gate was defined, so its present structure is provisional pending explicit approval, not retroactively approved.

Only the existing Stratumnova/A25-workspace.hub repository on main. No new branch/fork/repo or old-repository writes. No implementation, server/phone actions or deployment by virtue of this staging folder.
